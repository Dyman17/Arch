## 🌳 Git-workflow (обязательно)

```
main            ← только через PR + ревью техлида
 ├── feature/<задача>
 ├── fix/<что-то>
 └── docs/<что-то>
```

```bash
git checkout main && git pull origin main
git checkout -b feature/название-задачи
# мелкие коммиты: feat:/fix:/docs:/chore:
git pull origin main          # перед каждой отправкой
git push origin feature/название-задачи
gh pr create --fill
# мержит ТОЛЬКО техлид: gh pr merge --squash
```

### Правила PR

- PR = одна задача
- Название: `feat: ...`, `fix: ...`, `docs: ...`
- Описание: что сделано, как проверить; для UI — скриншот
- **Свой PR не мержить самому**

## 🚫 Запрещено

- Писать/форсить в `main`
- Мержить без ревью техлида
- Коммитить `.env`, ключи, токены
- Ключи внешних API во фронте
- Удалять/переписывать чужие коммиты
- Большие «wip» коммиты без описания
- Начинать задачу без записи в `docs/tasks.md`
- **Менять `docs/api-flow.md` без PR** (сначала согласовать с техлидом)
- Клиенту ходить напрямую во внешние routing/STT/LLM API
- Выдумывать объекты не из каталога `places`

## 🎯 Как работать ИИ-агенту

1. Прочитай `docs/tasks.md` — задача, статус, ветка
2. Прочитай связанные флоучарты и **api-flow.md** — не изобретай контракты
3. Если архитектура/стек/провайдер неясны → остановись, спроси техлида
4. Работай только в своей ветке
5. Коммиты мелкие: `feat: add place card screen`
6. Обнови статус в `tasks.md` (⬜ → 🔄 → ✅)
7. Открой PR, опиши что/как проверить
8. Жди ревью — не мержи сам

### Скоуп

- **Backend-агент:** `backend/`, `data/` seed по согласованию. Не трогает UI.
- **Frontend-агент:** `frontend/`. Не ломает API-контракт; новый эндпоинт = задача + PR в `api-flow.md`.
- **Контракт:** фронт не придумывает эндпоинты; бэк не меняет ответы молча.

### Деградация (обязательно из user-flow)

Ошибка STT → экран повтора + выбор касанием. Нет сети → кэш каталога. Нет routing → прямая линия + `is_approximate`. Нет HuskyLens → полный режим касания.

## 🔄 Синхронизация

- Каждые 2–3 часа: `git pull origin main`, статусы в `tasks.md`

- Техлид периодически мержит проверенные PR

## ✅ Definition of Done (задача)

- [ ] Ветка от актуального `main`, запушена
- [ ] Конфликтов нет
- [ ] Работает локально (ручная проверка)
- [ ] `tasks.md` = ✅
- [ ] PR открыт, описание заполнено
- [ ] Ревью техлида → замержено

## ✅ Definition of Done (MVP проекта)

Человек впервые видит стеллу → выбирает место или спрашивает голосом → понимает направление → открывает TarihSky → QR маршрут на телефон. Демо **на целевом устройстве**; при ошибке речи главное доступно касанием.
