## Процесс стыковки (по шагам)

1. **Бэк поднимает заглушки первым.** До реальной логики — все эндпоинты отдают seed-JSON из `backend.md` с кодом 200. Фронт начинает сразу, не ждёт.
2. **Фронт ходит только по `frontend.md`.** Порядок вызовов и обработка ошибок — там.
3. **Сверка типов.** Поле есть в контракте — есть в ответе. Нет «лишних» полей без согласования, нет переименований молча.
4. **Интеграционный прогон** (техлид): сквозной сценарий голос → маршрут → QR на одном девайсе.
5. **Заморозка.** После рабочей интеграции контракт меняется только PR в `docs/api/` через техлида.

## Железные правила

- Base URL: `/api`. JSON, UTF-8. Основные языки: `kk` | `ru` | `en` (без иерархии, default `kk`); любой другой язык — через LLM/TTS
- `session_id` (uuid) фронт генерит один на сеанс, шлёт в `voice`/`qr`
- `bearing_deg` считает **только бэк**. Фронт рисует
- Ключи внешних сервисов — **только на сервере** (`.env`, не в репо). Фронт во внешние API не ходит
- Ошибки — только форматом `{ error: { code, message, details } }`, коды — из `backend.md`
- Ломаешь контракт — сначала PR в `docs/api/`, потом код

## Типичные ошибки подключения (не повторять)

| Ошибка | Как правильно |
|--------|---------------|
| Фронт сам считает азимут/расстояние | Брать `bearing_deg`, `distance_m`, `duration_min` из `route` |
| Забыли `lang` → тексты не на том языке | Всегда слать `lang` (или `auto` в `voice`) |
| Новый `session_id` на каждый запрос | Один на сеанс |
| Игнор `is_approximate` | Показывать пометку «примерный путь» |
| Игнор `has_scene: false` | Скрывать кнопку TarihSky, а не ловить 404 |
| Игнор `is_open_now: false` | Бейдж «закрыто», а не маршрут в никуда |
| Игнор `access: transit` | Показывать способ поездки, а не пеший путь |
| Нет обработки `422`/`503` | error_speech / прямая линия (см. `frontend.md`) |
| QR не обновляется | Таймаут 30 сек, возврат к карточке |
