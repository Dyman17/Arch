# 💡 Идея проекта — BaGdar

> Кейс Smart City Aktau. **Решение: делаем BaGdar.** Остальное — запасные.

---

## ✅ Основная идея: BaGdar — цифровой гид по Актау и Мангистау

**Бағдар — интерактивный туристический гид по Актау и Мангистау в формате городской стелы. Управление полностью голосовое (позже + жесты): никаких кнопок, каталогов и переключателей.** Турист просто подходит и говорит на своём языке. Первая версия — прототип: **обычный (не сенсорный) монитор + микрофон + динамик + камера**, подключённые к ноутбуку/мини-ПК. Касаний нет вообще: пробуждение — голосом или камерой (подошёл человек).

### Основной пользовательский сценарий (только речь)

1. Турист подходит к стеле. Стелла просыпается сама и здоровается.
2. Турист спрашивает на своём языке — например: *«Как пройти к музею?»*
3. Система понимает вопрос и язык, находит место в проверенном каталоге и отвечает вслух + коротко на экране.
4. Карта сама приближает объект, показывает маршрут от стелы, расстояние, время и стрелку направления.
5. По голосовой просьбе — история «Тогда и сейчас» или QR на телефон (*«Покажи как было раньше»*, *«Отправь на телефон»*).

### Управление — полностью ИИ («говорящий стенд»)

Никаких кнопок и меню. Стеллой управляет диалог с ИИ:

- понимает свободную речь на любом языке (kk/ru/en основные + остальные через LLM)
- ведёт разговор: отвечает, уточняет, предлагает («Показать как это место выглядело раньше?»)
- сам решает, что показать: карту, маршрут, историю, QR
- **Память сеанса:** помнит язык, текущее и прошлые места, ход разговора — понимает «а что рядом с ним?», «а как туда пройти?», «покажи ещё». **Память обнуляется с каждым пользователем** (прощание, тишина 90 сек, сон) — новый человек = чистый лист. Это же ответ на приватность: ничего не храним между людьми, только анонимная аналитика для дашборда.

### Исторический режим TarihSky — «Тогда и сейчас»

Из карточки места турист открывает сравнение современного вида и исторической реконструкции. Ползунок позволяет плавно переходить между изображениями. Рядом — короткая историческая справка на выбранном языке.

Для демонстрации готовим 2–3 сцены заранее, желательно с одинаковым ракурсом изображений. ИИ отвечает на вопросы на основе проверенных материалов. Реконструкции обозначаются как художественные; их генерация в реальном времени в первую версию не входит.

### Объём первой версии

- Один район Актау и **10–20 проверенных объектов**
- Карта-экран (только показ, трогать нечего)
- Диалог голосом: вопрос → ответ → уточнения → команды («покажи историю», «отправь на телефон», «что рядом»)
- Маршрут, расстояние, время и стрелка — по голосовой просьбе или сразу
- QR на телефон — по голосовой просьбе
- «Тогда и сейчас» для 2–3 объектов — по голосовой просьбе
- Язык — только автоопределение, кнопок нет
- Сон с часами, пробуждение звуком или касанием (касание — только будильник, не управление)

**Не в v1:** фото с генерацией фона, погода, озвучивание, сложные жесты. Языки утвердить до разработки.

### Техническая основа

| Часть | Предложение | Ответственность |
|---|---|---|
| Frontend | React + TypeScript + Vite, MapLibre | Интерфейс стеллы, запись голоса, карта, карточки, ползунок, QR |
| Backend | Python + FastAPI | Каталог, речь, вопросы, ИИ, маршруты |
| Данные | Каталог + статические изображения | Координаты, описания, переводы, часы, источники, сцены |
| Оборудование | ПК/экран/микрофон; HuskyLens по готовности | Запуск, приветствие при подходе |

Маршрут и расстояние — из сервиса маршрутизации; ИИ — понимание запроса и формулировка. **Ключи внешних сервисов — только на сервере.**

### Порядок разработки

1. Утвердить точку, объекты, языки, демо-сценарий
2. Зафиксировать архитектуру, задачи, API в документации
3. Карта → карточка → маршрут → QR
4. Текстовый вопрос → затем голос
5. Исторические сцены и переходы
6. Приложение на устройстве + полный сценарий с людьми
7. HuskyLens, если основное стабильно

### Критерий готовности

Человек, который впервые видит стеллу, сам спрашивает голосом, понимает направление, просит историю и QR — не коснувшись экрана ни разу. Демо на целевом устройстве; при ошибке речи стелла переспрашивает голосом.

Точка установки и ориентация стелы задаются заранее. Направление — относительно стелы. Для объектов вне пешей доступности — способ поездки голосом.

### Железо и доступность

- Стелла: не сенсорный монитор + микрофон + динамик + камера. Касаний нет.
- **Слепые:** покрыты — вопрос голосом + озвучка ответа (B11).
- **Немые (и глухие):** камера считывает язык жестов → транскрибация в текст → дальше обычный диалог. **Авто-предложение:** человек рядом, а речи нет 10 секунд → на экране алерт «Общаетесь на языке жестов? Показывайте!» → включается чтение жестов. Старт: MediaPipe Hands (21 точка кисти) + 3–5 статичных жестов («да», «нет», «спасибо», цифры для выбора). Полный жестовый язык — за рамками хакатона, идёт в roadmap как эксперимент.

Турист подходит — стелла здоровается → вопрос на его языке → ответ + карта и путь → «покажи как было» → TarihSky → «отправь на телефон» → QR. Ни одного касания. В конце — дашборд акимата.

## 💭 Запасные идеи

### МестоLive — P2P-сеть обмена парковочными местами

Боль: час пик у набережной, «Дины», Aktau Mall — машины кружат впустую. Решение без железа: CV-камера видит выезд → заявка → первый в листе ожидания получает пуш, 2 минуты на подъезд. Рейтинг доверия вместо денег. MVP: карта Актау, симуляция, YOLO, очередь, таймер, дашборд акимата. Риски: приватность номеров, сложное демо из 4 частей.

### Осанка — скрининг позвоночника школьников

Камера 10 сек → метрики скелета → «риск сколиоза» (скрининг, не диагноз) + дашборд школ Актау. Плюсы: pose из коробки, неубиваемое демо. Минусы: медицинский формулинг, свет.
